# paranoid-tg-proxy

Установщик **WEB proxy для Telegram** на выделенном VPS, основанный на [telegramdesktop/tproxy-server](https://github.com/telegramdesktop/tproxy-server). Использует HTTPS/WebSocket, Caddy и внутренний MTProxy. **Это не публичный MTProto-прокси**: снаружи предполагается доступ через HTTPS на домене.

> **Ограничения:** проект `tproxy-server` экспериментальный. WEB proxy должен поддерживаться именно используемой версией Telegram-клиента. Наличие HTTPS и работающей bridge-страницы ещё не доказывает работоспособность в Telegram. Никакая конфигурация не гарантирует защиты от обнаружения или блокировки IP-адреса.

## Архитектура

```text
Telegram (клиент с поддержкой WEB proxy)
       | HTTPS / WebSocket, TCP 443
       v
 Caddy + сайт на puh.maxmir.ru
       | авторизованный bridge-запрос
       v
 tproxy-server (локальный relay)
       |
       v
 MTProxy (внутренний backend)
```

Обычный посетитель видит статический сайт по HTTPS. Доступ к bridge зависит от пути и секрета. Внешние порты внутреннего backend должны быть закрыты файрволом. Сайт и TLS **не делают прокси невидимым** для активного сканирования или анализа трафика.

## Для какого сервера предназначен

- Выделенный VPS с **Debian 12+ или Ubuntu 22.04+**, `x86_64` и доступом `root`/`sudo`.
- Домен **`puh.maxmir.ru`** с A-записью на публичный IPv4 этого VPS.
- Email для ACME/Let's Encrypt: **`lituslitus@gmail.com`**.
- Каталог сайта: **`/var/www/puh.maxmir.ru`**.
- Открытые снаружи TCP-порты 80 и 443, а также SSH (обычно 22) для администрирования.
- Сервер не должен обслуживать другие сайты через Caddy: upstream-установщик может заменить `Caddyfile`.

Все три значения (домен, email, каталог) **записаны в `install.sh`**. Прежние флаги `-d`, `-e` и `-s` больше не используются. Для другого сервера их надо поменять в начале файла.

## Сайт (статическая главная страница)

Если файла `/var/www/puh.maxmir.ru/index.html` нет, новый `install.sh` **создаёт его автоматически**: простую автономную страницу «MaxMir — цифровые заметки», без внешних скриптов и счётчиков. Если `index.html` уже существует, он не перезаписывается.

Эта страница служит обычной главной страницей сайта. Она **не является гарантией маскировки**. Если нужна индивидуальная страница, отредактируй `index.html` самостоятельно.

## Установка с нуля

Сначала проверь содержимое скриптов на GitHub. На VPS:

```bash
git clone https://github.com/lituslitus-cyber/paranoid-tg-proxy.git
cd paranoid-tg-proxy
sudo bash install.sh --no-blocklist
```

`--no-blocklist` отключает **дополнительный** IP-блоклист сканеров, но не штатную настройку backend-файрвола upstream. Это рекомендуемый первый запуск: сторонние блоклисты могут ошибочно ограничить доступ и затруднить диагностику.

После выполнения проверки:

```bash
sudo bash install.sh --check
```

Получить ссылку (содержит **секрет**, не публиковать):

```bash
sudo cat /etc/paranoid-webproxy/client-link.txt
```

В файле две формы ссылки: `https://t.me/webproxy?...` и `tg://webproxy?...`. Клиент должен поддерживать этот тип прокси. Не заменяй секрет из ссылки на исходный hex-секрет: используется **marked secret** и сервер с **base_path**.

## Если на VPS уже была старая установка

В репозитории есть отдельный `cleanup.sh` для выделенного VPS. **Он удаляет специализированную конфигурацию прокси, останавливает Caddy и удаляет его Caddyfile**, поэтому не применяй его на сервере с другими сайтами.

```bash
cd ~/paranoid-tg-proxy
git pull origin main
sudo bash cleanup.sh --apply
```

Перед удалением скрипт сохраняет закрытый архив резервной копии в `/root/proxy-backup-*.tar.gz`. Архив может содержать секреты: не публикуй и не пересылай его без редактирования. Каталог `/var/www/puh.maxmir.ru` очистка сохраняет. Скрипт не удаляет SSH, не удаляет системные пакеты и не выполняет глобальный `nft flush ruleset`.

**Внимание:** статус SSH и правил сетевого доступа всё равно необходимо проверять до применения cleanup; автоматическая очистка не гарантирует отсутствие конфликтов с вручную изменёнными службами.

Затем повтори установку командой `sudo bash install.sh --no-blocklist`.

## Что делает `install.sh`

1. Проверяет ОС, архитектуру, DNS, внешний IPv4 и состояние портов.
2. Создаёт `index.html`, если его нет; сохраняет существующую страницу.
3. Устанавливает необходимые системные пакеты без общего `apt upgrade`.
4. Создаёт резервные копии существующих конфигураций в `/etc/paranoid-webproxy/backups/`.
5. Загружает актуальную ветку `master` upstream `tproxy-server` и запускает его установщик (Caddy, relay, внутренний MTProxy, файрвол) с `base_path` и новым секретом.
6. Формирует ссылки WEB proxy с **base_path** и **marked base64url secret** в `/etc/paranoid-webproxy/client-link.txt` (доступ только root).
7. Проверяет службы, локальный endpoint `/readyz`, HTTPS и авторизованную bridge-страницу.

> Использование `master` означает, что поведение upstream может измениться. Перед повторной установкой просматривай изменения и помни: скрипт **перевыпускает секрет**, так что старые клиентские ссылки перестанут работать.

## Дополнительный блоклист (необязательный)

Если запустить просто `sudo bash install.sh` без `--no-blocklist`, установщик дополнительно попытается загрузить список известных сканеров и применить фильтрацию в таблице `inet paranoid_scanners`. Фильтрация направлена на входящий **TCP 443**; SSH и TCP 80 напрямую этими правилами не затрагиваются. Устанавливается таймер `paranoid-scanner-update.timer`.

Блоклист из сторонних источников может ошибаться, устаревать или быть недоступен; он не защищает от DPI и не гарантирует предотвращения сканирования или блокировки. Для первоначальной настройки рекомендуется `--no-blocklist`.

## Диагностика

```bash
sudo bash install.sh --check
systemctl status caddy mtproxy tproxy-server tproxy-firewall --no-pager
sudo journalctl -u caddy -u mtproxy -u tproxy-server --since '30 minutes ago' --no-pager
sudo nft list tables
```

**Важно:** режим `--check` выводит состояния служб и доступности сайта; сам по себе он не проверяет реальное подключение Telegram и не гарантирует, что все компоненты полностью исправны. Для итоговой проверки необходимо подключиться клиентом с поддержкой WEB proxy.

Внешние порты внутреннего backend не должны быть доступны из Интернета. Не включай в публичные логи полные URL, bridge-токены, секреты и приватные ссылки.

## Ограничения и безопасность

- Невозможно гарантировать, что ТСПУ/РКН не обнаружат или не заблокируют сервер. HTTPS на 443 и статический сайт не устраняют возможность блокировки по IP и анализа поведения соединений.
- Установка/обновление upstream и применение правил nftables меняют конфигурацию системы. Тестируй на выделенном VPS; обеспечь доступ через консоль провайдера на случай потери SSH.
- При переустановке создаётся новый секрет; клиентскую ссылку нужно обновить.
- Не публикуй `/etc/paranoid-webproxy/client-link.txt`, файлы секретов, частные конфигурации и архивы резервных копий.
- README описывает **реализацию скриптов в данном репозитории**, а не официальные гарантии Telegram или upstream.
