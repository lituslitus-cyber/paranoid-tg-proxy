# paranoid-tg-proxy

Установщик WEB proxy для Telegram на базе [telegramdesktop/tproxy-server](https://github.com/telegramdesktop/tproxy-server) плюс блоклист сканеров на nftables.

Снаружи сервер выглядит как обычный сайт на твоём домене: 443 порт, настоящий сертификат Let's Encrypt, твоя собственная страница. Запрос без правильного bridge-токена получает только эту страницу.

> **Статус.** README самого tproxy-server всё ещё называет его proof-of-concept, но тип прокси WEB уже встроен в официальные клиенты Telegram (список ниже). Сам скрипт новый, первый запуск делай на чистом VPS.

## Как это работает

```
Telegram-клиент (с поддержкой WEB proxy)
        |  HTTPS / WebSocket на твой домен
        v
  Caddy :80/:443  ->  tproxy-server (127.0.0.1:8080)  ->  официальный MTProxy (127.0.0.1:2398)
```

- Клиент шифрует трафик как для MTProxy, но отправляет его внутри HTTPS-канала через WebView.
- Relay и MTProxy слушают только loopback. Порты 2398 и 8888 дополнительно закрыты правилом nftables.
- Hostname и секрет вместе дают токен доступа. Без него сайт отдаёт обычную страницу.
- Блоклист сканеров (ГРЧЦ, CyberOK и другие) режется на уровне ядра, таблица `inet rkn_block`. Она восстанавливается из кэша после перезагрузки и обновляется раз в сутки.

## Что делает скрипт

1. Проверяет окружение до любых изменений: root, x86_64, Ubuntu 22.04+ или Debian 12+, формат домена, что A-запись указывает на этот сервер, что 80 и 443 свободны.
2. Генерирует секрет (16 байт) и сохраняет в `/root/.tg-proxy-secret`. При повторном запуске секрет не меняется.
3. Скачивает tproxy-server и запускает его официальный установщик: Caddy, MTProxy, relay, nftables, сертификат.
4. Настраивает блоклист: `/usr/local/sbin/rkn-blocklist-update.sh`, таймер `rkn-blocklist.timer` и drop-in для `nftables.service`.
5. Проверяет результат: health и readiness relay, одинаковый ответ на верный и неверный `?bridge=`, наличие блоклиста.
6. Печатает hostname, секрет и ссылку для клиента.

Скрипт не делает `apt upgrade`, не ставит UFW и fail2ban.

## Требования

- Чистый VPS: x86_64, публичный IPv4, Ubuntu 22.04+ или Debian 12+, root.
- Домен (строчными буквами) с A-записью на IP сервера. Не ставь перед ним CDN или HTTP-прокси.
- **Свой статический сайт** с `index.html`. Готовой заглушки в репозитории нет намеренно: одинаковый сайт у многих операторов становится сигнатурой для активного зондирования.
- В файрволе хостера открыты только TCP 22 (лучше только с твоего IP), 80 и 443.

## Установка

```bash
git clone https://github.com/lituslitus-cyber/paranoid-tg-proxy.git
cd paranoid-tg-proxy
sudo bash install.sh -d proxy.example.com -e you@example.com -s /путь/к/сайту
```

| Флаг | Значение |
|------|----------|
| `-d` | домен |
| `-e` | почта для Let's Encrypt |
| `-s` | каталог со своим сайтом (нужен `index.html`) |

Переменная `TPROXY_REF` задаёт ветку или тег tproxy-server (по умолчанию `master`). Для постоянного использования закрепи тег: скрипт печатает хэш установленного коммита.

Скрипт запускай из клонированного репозитория или скачай файл и проверь его перед запуском. Не запускай его через `curl | bash`.

## Подключение клиента

Тип прокси WEB есть в официальных клиентах:

- **Telegram Desktop 7.1+** (на Windows лучше 7.1.2 и новее: в 7.1.0 и 7.1.1 был баг WebView2).
- **Telegram для iOS 13.0+**.
- **Telegram для Android**: тип WEB есть в списке прокси, но по ряду источников он ещё считается экспериментальным. Ему нужен актуальный Android System WebView.

Меню: Настройки → Данные и память → Прокси (Desktop: Настройки → Продвинутые → Тип соединения). Версии и статус могут меняться, сверяйся с актуальными релизами.

Нужны два значения:

```
Hostname: proxy.example.com   (без https:// и порта)
Secret:   <32 hex-символа из вывода скрипта>
```

Ссылка (печатается в конце установки):

```
tg://webproxy?server=proxy.example.com&secret=<secret>
```

Ссылка `tg://webproxy` открывается прямо в клиенте. Вариант `https://t.me/webproxy?...` в README upstream описан как не зарегистрированный на публичном t.me, я это не перепроверял: если не откроется, используй `tg://` или введи hostname и секрет вручную.

## Блоклист

- Источники: списки antiscanner (shadow-netlab) и CyberOK Skipa, плюс несколько адресов в самом скрипте.
- Принимаются только IPv4 и IPv4/CIDR с префиксом от /8 до /32. Если скачалось меньше 20 записей, остаётся прежний кэш.
- Белый список: `/etc/rkn-blocklist.allow`, по одному IP или подсети в строке. Туда при установке попадает IP твоей SSH-сессии. Если ты подключаешься с другого адреса, добавь его, иначе возможна блокировка.
- Принудительное обновление: `sudo systemctl start rkn-blocklist.service`
- Проверка: `sudo nft list set inet rkn_block rkn4 | head`

Блоклист не защищает от DPI оператора и не делает трафик невидимым. Он только отсекает известные сканеры.

## Проверка и диагностика

```bash
systemctl status caddy tproxy-firewall mtproxy tproxy-server
curl -fsS http://127.0.0.1:8081/healthz
curl -fsS http://127.0.0.1:8081/readyz
journalctl -u tproxy-server -u mtproxy -u caddy --since '30 minutes ago'
```

С другого компьютера порты 2398, 8080, 8081, 8888 должны быть недоступны. Не включай логирование полных URI и заголовков в Caddy: в них может попасть bridge-токен.

## Обновление

- Relay: `sudo ./deploy/update-relay.sh` из каталога `/opt/tproxy-server-src` (после `git pull`). Активные сессии при этом сбросятся.
- Повторный запуск `install.sh` целиком заменит конфиг и Caddyfile. Делай это осознанно.

## Ограничения

- Upstream называет tproxy-server proof-of-concept, протокол и клиентская поддержка ещё развиваются. После обновления клиента проверяй, что соединение работает.
- На Android WEB proxy описывают как экспериментальный. Если не подключается: обнови Android System WebView, заново скопируй hostname и секрет (одна неверная буква оставляет клиент в «Подключение»).
- WEB proxy не скрывает сам факт использования Telegram от оператора, который умеет разбирать трафик глубже. Не рассчитывай на него как на гарантию.
- Установщик tproxy-server рассчитан на чистый сервер и заменяет активный Caddyfile. Если на сервере уже есть другие сайты, используй ручную интеграцию из документации upstream.
- Если на сервере активен UFW, он может конфликтовать с nftables. Рекомендуется отключить его и использовать файрвол хостера.
- Скрипт передаёт секрет установщику через `--secret`, поэтому на время установки он виден в списке процессов. Запускай его только на сервере, где нет посторонних пользователей.
- Блоклист и прокси не гарантируют обход блокировок. Используй на свой риск и в соответствии с законодательством своей страны.

## Откат

```bash
sudo systemctl disable --now rkn-blocklist.timer
sudo nft delete table inet rkn_block
sudo rm -f /etc/systemd/system/rkn-blocklist.{service,timer} \
           /etc/systemd/system/nftables.service.d/rkn-blocklist.conf \
           /usr/local/sbin/rkn-blocklist-update.sh /etc/rkn-blocklist.allow
sudo rm -rf /var/lib/rkn-blocklist
sudo systemctl daemon-reload
```

Удаление самого tproxy-server (Caddy, MTProxy, relay) смотри в документации [upstream](https://github.com/telegramdesktop/tproxy-server). Автоматического удалителя там нет, я его не видел.
